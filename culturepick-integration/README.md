# 컬처픽 기능 연결 테스트

주소: http://127.0.0.1:4174/
실행: node culturepick-integration/server.cjs

## 현재 연결 범위
- 기존 로컬 운영 자료 pohang-ontime/data/programs.json을 읽는다. 운영 웹의 최신 배포 여부는 별도 확인한다.
- 기존 신청 전송 형식으로 변환한 뒤 로컬 모의 서버로 전송한다. 실제 Apps Script·Google Sheets·SOLAPI에는 연결하지 않는다.
- 모의 번호 01000000000 사용. 선택한 강좌 ID만 별도 브라우저 저장소에 보관한다.
- 모의 서버는 번호를 가리고 결과를 메모리에만 보관한다. 종료 시 결과가 삭제된다.
- /api/status에서 모의 저장 결과와 접수 15분 전 계산 시각을 확인할 수 있다.
- 신청 화면의 '다음 저장 실패 시험'으로 실패 후 재시도를 시험한다.
- 이 폴더는 GitHub Pages 배포 경로 밖이다. 원래 디자인 미리보기는 4173에서 유지된다.

## 검증 결과 및 남은 단계
- 기존 전송 항목 호환성과 리마인더 등 자동 테스트 58개 통과.
- 브라우저에서 담기 → 목록 → 번호/동의 → 의도적 저장 실패 → 재시도 성공 확인.
- 실제 시트 저장 및 별도 시험 예약·휴대폰 수신 확인 완료.
- 로컬 중복 방지 성공은 운영 Apps Script의 중복 방지 보장이 아니다.
- 기존 운영의 no-cors 전송은 응답만으로 시트 저장 성공을 증명할 수 없다. 실제 시트와 예약 기록 확인이 필요하다.
- 저장 정보 승계와 수집 데이터 계약 자동 검증 완료. 실기기 숫자 키패드는 보류, GA 실유입은 배포 후 확인한다.
- 로컬 Apps Script 파일과 현재 실제 배포된 버전의 일치 여부부터 확인한다. 복사본을 곧바로 덮어쓰지 않는다.

## 배포 직전 복원 지점
복원 태그 생성·원격 보관 완료. 운영 화면 배포 전이다.
1. GitHub Pages에서 실제 배포 중인 커밋 번호를 확인한다. 로컬 HEAD와 같다고 가정하지 않는다.
2. 해당 커밋에 날짜가 있는 주석 태그(before-design-날짜-시각)를 붙여 원격에 보관하고 배포 결과물도 확보한다.
3. 새 디자인은 독립 커밋으로 배포하고, 변경 파일 목록과 검증 결과를 기록한다.
4. 문제가 있으면 디자인 변경을 되돌리는 새 커밋으로 재배포한다. 전체 저장소를 과거로 강제 초기화하지 않는다.
5. 복원할 때 최신 programs.json과 index.html의 programsData/sourceUpdatedAt/dataUpdatedAt을 유지해 기관 자료가 과거로 돌아가지 않게 한다.
6. 시트 신청 내역과 이미 발송한 문자는 화면 복원으로 되돌아가지 않는다. Apps Script를 바꿀 경우 실제 배포 버전도 별도로 기록한다.

복원 완료 확인: 이전 화면, 신청 경로, 강좌 최신성, 기존 링크, Pages 성공 상태를 확인한다.
