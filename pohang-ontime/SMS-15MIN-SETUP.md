- 시험 결과: 2026-09-05 가상 접수 17:50 KST, 예약 17:35 KST, 업체 발송 기록 17:35:00.245 KST, 성공 1건/실패 0건. 15분전예약 탭 상태는 발송완료입니다. 휴대폰의 실제 수신 시각 확인은 대기 중입니다.
- 시험 결과 조회용 십오분전자동실행 트리거 1개가 동작합니다. CP15_ENABLED는 false이므로 실제 신청자의 신규 예약은 활성화되지 않았습니다.
- GitHub Pages 배포는 Apps Script를 갱신하지 않습니다. 현재 웹페이지의 카톡/아침 알림 문구는 운영 검증 후 문자/15분 전 기준으로 별도 반영해야 합니다.

## 동작

접수 시각에서 15분을 뺀 시각을 SOLAPI에 미리 예약합니다. 예: 10:00 접수 → 09:45 예약. Apps Script가 매분 새 신청을 확인하고 향후 24시간 안의 알림을 예약합니다. 문자 발송 시각은 SOLAPI가 처리하므로 Google의 반복 실행 시각에 맞춰 즉시 문자를 보내는 구조가 아닙니다.

- 발송목록 탭이 있으면 사람×강좌 단위로 읽고, 현재 운영본처럼 없으면 신청자 탭의 모든 행과 찜 ID를 읽습니다.
- 사람×강좌×접수시각마다 한 건을 예약합니다. 여러 강좌를 선택했다면 각 강좌의 접수 시각에 맞춰 별도 문자가 나갑니다.
- 시각은 한국시간으로 해석합니다. 날짜만 있거나 잘못된 시각이면 예약하지 않습니다.
- 이미 15분 전 시각을 지난 신청은 즉시 문자를 보내지 않고 시각지남으로 남깁니다. 경계 직전 신청이나 장시간 실행 장애는 예약을 놓칠 수 있으므로, 접수 임박 신청 안내는 운영 검증 후 화면에 반영해야 합니다.
- 그룹 ID를 저장한 뒤 메시지를 추가하고 예약합니다. 응답이 끊기면 같은 그룹을 조회하므로 자동 재시도로 중복 예약하지 않습니다.
- 예약은 수신 완료가 아닙니다. 업체 처리 결과와 실제 휴대폰 수신 시각을 구분합니다. 통신사/단말 상황 때문에 수신은 예약 시각보다 늦을 수 있습니다.
- 기존 보내기 함수는 CP15_ENABLED=true일 때 중복 발송을 막기 위해 중지됩니다. 과거 발송함의 대기 문자를 같이 보내지 마세요.

## 설정

기존 운영 SOLAPI 설정을 재사용할 수 있습니다. 새로 설정한다면 Apps Script의 프로젝트 설정 → 스크립트 속성에 다음 이름으로 입력합니다. 저장소에 실제 값을 적지 않습니다.

| 속성 | 값 |
| --- | --- |
| SOLAPI_API_KEY | SOLAPI 키 |
| SOLAPI_API_SECRET | SOLAPI 비밀키 |
| SOLAPI_FROM | 등록한 발신번호 |
| CP15_TEST_PHONE | 명시적으로 동의한 본인 시험 수신번호 |
| CP15_TEST_OPEN_AT | 한국시간 가상 접수 시각, YYYY-MM-DD HH:mm |

신규 설치 시 Apps Script에 apps-script-reminders.js를 접수15분전예약.gs로 저장합니다. 문자발송.gs는 운영 비밀값을 유지하면서 저장소의 보내기 함수 앞부분 중복 방지 조건만 적용합니다. 시트와 Apps Script 시간대는 Asia/Seoul입니다. 설정 점검에 Google 권한 검토가 나오면 계정 소유자가 요청 범위를 확인하고 승인합니다.

## 본인 번호로 시험

1. 십오분전설정확인 실행: 설정 유무, 시간대, enabled=false 확인. 이 함수는 문자 API를 호출하지 않습니다.
2. 본인의 시험 번호와 시험 문자 1건 발송 동의를 확인합니다. 발신번호를 본인 수신번호로 자동 추정하지 않습니다.
3. 가상 접수 시각을 현재보다 약 20분 뒤로 지정합니다. 최소 17분 이상 뒤여야 합니다. 예정 발송은 가상 접수 15분 전, 즉 약 5분 뒤입니다.
4. 십오분전시험예약 실행: 시험 데이터만 15분전예약 탭에 남기며 CP15_ENABLED를 켜지 않습니다. 시험 결과 조회용 매분 트리거가 만들어집니다.
5. 시트 상태가 예약이고, 예약발송시각이 가상 접수 시각보다 정확히 15분 빠른지 확인합니다. 저장된 시각은 UTC ISO 8601 형식이며 Z 시각에 9시간을 더하면 한국시간입니다.
6. 발송 후 업체 결과가 발송완료인지 확인하고, 휴대폰 수신 시각을 별도로 기록합니다. 예약 성공만 보고 시험 성공으로 처리하지 않습니다.
7. 같은 시험 예약을 중복 실행하더라도 문자 한 건만 존재하는지 확인합니다. 코드의 모의 검증은 응답 유실 후 같은 그룹 조회 복구를 포함합니다.

시험 예시 내용: [컬처픽 시험] 접수 15분 전 알림 / 수신 시각 확인용 시험 / 접수 시작: MM/DD HH:mm / 접수 전 로그인을 준비해 주세요 / 서비스 주소 / 수신거부: 그만 회신. 실제 서비스와 같은 내용 길이를 사용하므로 LMS로 처리될 수 있습니다. 실제 과금은 SOLAPI 설정/요금에 따릅니다.

## 전체 자동 예약 활성화 / 정지

본인 수신 검증 후 십오분전미리보기에서 대상과 시각을 확인하고 십오분전자동설치를 실행합니다. 이 함수는 실제 신청자 대상으로 자동 예약을 켭니다. 기존 보내기 트리거가 있으면 설치를 중단합니다. 다른 함수의 트리거는 삭제하지 않습니다.

십오분전자동중지는 CP15_ENABLED를 끄고 이미 맡긴 운영/시험 예약의 취소를 요청합니다. 취소 실패는 확인필요로 남고 트리거가 계속 확인합니다. SOLAPI가 이미 발송 중이면 취소되지 않을 수 있습니다. 그룹 상태를 확인하기 전에 트리거만 삭제하지 마세요.

수신거부 탭의 A1을 휴대폰으로 만들고 A열에 번호를 기록하면 해당 번호의 신규 예약을 제외하고 기존 예약 취소를 요청합니다. 발송목록을 쓰는 경우 H열에 취소/수신거부/발송완료 등을 표시해도 제외됩니다. 현재 신청자 방식에서는 해당 강좌 행 삭제 또는 수신거부 탭으로 관리합니다. 문자 회신을 자동으로 읽는 기능은 이번 변경에 포함되지 않으므로 그만 회신은 운영자가 수신해 즉시 반영해야 합니다.
