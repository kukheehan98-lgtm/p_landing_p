# 우리동네 컬처픽_포항

포항의 무료 강좌·전시를 모아 보여주고, **접수가 열리는 날 문자로 알려주는** 서비스입니다.

**사이트** — https://kukheehan98-lgtm.github.io/p_landing_p/
**타깃** — 30~40대 유아·초등 학부모
**메시지** — 「작은 정원 · 선착순」. 정원 60명은 알림이 없어도 신청되지만, 6가족은 못 잡습니다.

## 서버가 없습니다

이 서비스에서 「백엔드」라 부를 수 있는 건 **앱스크립트 두 개**뿐입니다. 나머지는 정적 파일이거나, 하루 몇 번 도는 배치 작업입니다.

| 층 | 무엇 | 어디서 도는가 |
| --- | --- | --- |
| **화면** | `index.html` 한 장 | 방문자 브라우저. GitHub Pages 는 파일을 내어줄 뿐 |
| **데이터 파이프라인** | `crawler/*` | 이 PC와 깃허브 서버에서 하루 몇 번. 요청을 받지 않음 |
| **백엔드** | 앱스크립트 2개 | 구글. 신청을 받고, 문자를 보냄 |
| **데이터베이스** | 구글 시트 | 신청자 명단 |

강좌 데이터는 **화면 안에 박혀 있습니다.** `index.html` 안의 `<script type="application/json" id="programsData">` 블록을 수집기가 통째로 갈아 끼웁니다. 그래서 화면을 그릴 때 네트워크 요청이 없습니다.

| `data/programs.json` | 같은 데이터의 기록용 사본. 변경 이력이 git 에 남습니다 |

| 파일 | 역할 |
| --- | --- |
| `parser.js` | 기관 HTML/JSON → 강좌 데이터. **어댑터 4개** (phlib / gbelib / gsei / phcf) |

## 왜 이렇게 만들었나

### 상태를 저장하지 않고 계산한다
「마감됨」을 데이터에 적어두면 매일 누가 고쳐야 합니다. 대신 **날짜만 저장하고 상태는 화면이 매번 계산**합니다 (`phase()`).

**수집이 며칠 멈춰도 지난 프로그램은 스스로 사라집니다.** 자동 파기의 전부가 이 한 줄입니다.

날짜만으로 계산한 「접수중 8건」이 도서관 사이트가 「접수하기」 버튼을 띄우는 8건과 정확히 일치하는 것을 확인했습니다.

### 큐레이션을 시트가 아니라 코드에 둔다
사람이 시트에 분류를 적어두면 매일 새벽 수집이 덮어씁니다. `curate.js` 에 규칙으로 두면 새 강좌가 들어와도 알아서 분류되고, 왜 그렇게 뽑혔는지 나중에 읽을 수 있습니다.

### 못 본 것과 사라진 것을 구분한다
기관 사이트가 막히면 결과가 0건으로 옵니다. 그대로 반영하면 화면이 텅 빕니다.
- 한 기관이 실패하면 **그 기관의 지난 데이터를 이어받고**, 나머지만 갱신
- 전부 실패하면 아무것도 쓰지 않음
- 개별 강좌는 **오직 날짜로만** 사라짐

### 문자는 준비와 발송을 나눈다
보낸 문자는 되돌릴 수 없습니다. `준비()` 가 대상을 「발송함」에 적고, 사람이 확인한 뒤 `보내기()` 를 누릅니다. 몇 주 문제없이 돌면 그때 자동으로 바꿉니다.

## 다시 밟으면 안 되는 함정

**작업 스케줄러가 `powershell.exe` 를 직접 부르면 검은 창이 깜빡입니다.**
`-WindowStyle Hidden` 을 줘도 창을 만들었다가 숨기는 방식이라 순간적으로 보일 수 있습니다.
사용자가 "컴퓨터를 뭔가 건드리는 것 같다"고 느낄 만큼 매일 여러 번 반복되면 신뢰에 영향을 줍니다.
→ `wscript.exe //B run-*-hidden.vbs` 를 거쳐 부르면 창 자체가 생기지 않습니다.

**`scroll-behavior: smooth` 는 애니메이션 프레임이 없으면 아무 일도 안 합니다.**
백그라운드 탭·절전 모드에서 `scrollTo` 와 `scrollLeft` 대입이 조용히 무시됩니다. 화면 전환이 실패해도 오류가 없어 원인을 찾기 어렵습니다. → 중요한 이동은 `scroll-behavior: auto` 로 잠시 바꿔 즉시 이동시킵니다.

**목록 전체를 다시 그리면 캐러셀이 되감깁니다.**
`renderCards()` 에는 필터용 되감기가 들어 있습니다. 담기처럼 카드 한 장만 바뀌는 동작은 `refreshCard()` 를 쓰세요.

**두 호스트가 같은 파일을 쓰면 줄바꿈과 순서로 싸웁니다.**
윈도우는 CRLF, 리눅스는 LF. 기관을 도는 순서도 다릅니다. → `.gitattributes` 로 LF 고정, 출력은 id 순으로 정렬.

**작업 스케줄러는 `pwsh.exe` 를 못 찾습니다.**
PowerShell 7 이 스토어 앱으로 깔리면 경로를 못 잡아 `0x80070002` 가 납니다. → `System32\WindowsPowerShell\v1.0\powershell.exe` 를 씁니다. 그 셸은 BOM 없는 `.ps1` 의 한글을 깨뜨리므로 **스크립트에 UTF-8 BOM 이 있어야 합니다.**

**실서비스 화면에서 신청 폼을 눌러 시험하면 실제 신청자 시트가 더러워집니다.**
그 시트에는 남의 전화번호가 있고, 되돌리는 방법은 손으로 행을 지우는 것뿐입니다.
신청 흐름을 브라우저로 확인할 때는 `window.fetch` 를 먼저 가로채고, 끝난 뒤
시트를 눈으로 확인하세요. 이 화면은 **기록·화면 표시를 먼저 하고 전송은 뒤에서**
하므로(그래서 68ms 로 빠릅니다), 제출 직후에 전송 여부를 재면 아직 안 보낸 상태를
「안 보냈다」로 오해할 수 있습니다. 시트를 직접 보는 것만이 확실한 확인입니다.

**앱스크립트 웹앱은 클라이언트가 오류를 봐도 이미 기록한 경우가 있습니다.**
curl 이 411/405 를 뱉었는데 시트에는 세 줄이 들어와 있었습니다. 재전송 로직을 손볼 때 중복 방지를 신경 쓰세요.

**태그 제거가 전시 제목을 삼킵니다.**
`<아침놀>` 이 HTML 태그로 오인돼 사라졌습니다. JSON 에서 온 값에는 `plain()` 을 쓰세요.

**정원 단위가 기관마다 다릅니다.**
과학원은 「6가족」입니다. `unit` 필드를 따라가야 합니다.

**축제는 접수기간 칸에 행사 날짜가 복사돼 있습니다.**
그대로 믿으면 신청이 필요 없는 행사에 「D-6 접수 시작」이 붙습니다.

## 운영

### 매일 아침
1. 「발송함」 탭에서 오늘 보낼 내용 확인
2. 맞으면 앱스크립트에서 `보내기()` 실행

### 뭔가 이상할 때 볼 곳
```
crawler/last-run.log         깃허브 수집 기록 (저장소에 커밋됨)
crawler/last-local-run.log   이 PC 수집 기록 (로컬 전용)
crawler/last-observe.log     관측 기록
저장소 Actions 탭             워크플로 성공/실패
```

### 손으로 돌려보기
```bash
node crawler/crawl.js --dry     # 수집만, 파일은 안 건드림
node crawler/observe.js --now   # 지금 정원 한 번 확인
```

### 예약 작업
```powershell
Get-ScheduledTask -TaskName '컬처픽 강좌 수집'
Get-ScheduledTask -TaskName '컬처픽 접수 관측'
Start-ScheduledTask -TaskName '컬처픽 강좌 수집'      # 지금 한 번
Unregister-ScheduledTask -TaskName '컬처픽 강좌 수집'  # 해제
```
